**Analytics → Liquidations** shows who can be liquidated now, how close everyone else is, and the liquidations already recorded on-chain.

## On the page

| Panel | What it shows |
|---|---|
| **KPI cards** | Can be liquidated now, liquidatable debt, bad debt (estimated), liquidations recorded |
| **Accounts that can be liquidated** | Every account with debt at a health factor of **1.10 or below** |
| **Closest to being liquidated** | Healthy accounts nearest the line |
| **Debt by risk** | How much debt sits in each risk band |
| **Past liquidations** | Liquidation events read from the chain |
| **Liquidation line** | How the 1.10 rule works |

## Candidate vs liquidated

<AccordionGroup>
  <Accordion title="A candidate isn't guaranteed to be liquidated">
    A liquidator still needs funds to repay all the debt, token allowances, fresh oracle prices and a transaction that fits Soroban's limits. If a plain collateral token can't be priced, the contract refuses to liquidate.
  </Accordion>
  <Accordion title="What a liquidator receives">
    The liquidator repays all recognized debt. In return they get Blend positions (withdrawn to them), LP tokens (transferred as-is) and every remaining token in the account.
  </Accordion>
  <Accordion title="After a liquidation">
    The margin account stays open and empty. A recorded liquidation event means the transaction ran; check the account's current state for details.
  </Accordion>
</AccordionGroup>

History can lag a few seconds behind the chain. Use the transaction hash on Stellar Expert to confirm.

See [Liquidation](/stellar/guides/margin/liquidation) and [Liquidation Bots](/stellar/developers/guides/liquidation-bots).
