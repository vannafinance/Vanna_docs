This reference describes `vanna-credit-layer` (three Anchor programs) and `vanna-credit-backend` (the Next.js app) as they run on the hosted Surfpool **mainnet fork**.

| Program | ID | Role |
|---|---|---|
| `vanna_credit_layer` (core) | `H37YVBG3eGtz89ofd7iDLc2PJgn12778392XeU2QJcGC` | Lending pools, margin accounts, health, liquidation, `margin_execute` |
| `vanna_oracle` | `FXY5DRfekMUTbUp4uyCFpCZmCccrp6kPq3hTM4GRihnc` | Values every holding: tokens from its price book, the Phoenix venue from its market book |
| `vanna_validator` | `6fND3vhtstp486iE6rsSNVUox3kcjNNRsSLAN7ZPs7th` | Decides which external calls a margin account may make |

The core knows no price source and no external protocol. Adding a protocol or a price source means a new file in the oracle or the validator, then an admin registration. The core is not redeployed.

Start with [Architecture](/solana/developers/architecture), [Configured Accounts](/solana/developers/deployed-contracts), and [Math Reference](/solana/developers/math-reference).

## Current scope

- **Lending pools** for USDC, USDT and SOL. Lenders receive vTokens.
- **One cross-margin account per wallet.** Every allowed token in it counts toward one health factor.
- **Collateral** includes SOL, USDC, USDT, JitoSOL, JupSOL, JupUSD, the xStocks (NVDAx, GOOGLx, AAPLx, TSLAx), and receipt tokens from Kamino, Perena and the basis vaults.
- **External calls through `margin_execute`**: Jupiter and Titan swaps, Kamino Lend supply / redeem, Phoenix perps (via Ember USDC ⇄ phUSD), Perena USD* vaults, and Vanna's delta-neutral basis vaults.
- **Liquidation** that is permissionless and partial, plus an admin write-off for dust bad debt.
